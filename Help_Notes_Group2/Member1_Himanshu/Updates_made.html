  • Enforced Rules: Min 2, max 5 co-owners.
  • Share Rule: Sum of sharePercent must equal 100% exactly (with 0.01 tolerance).
  • Minimum Share: Each co-owner must hold at least 1.0% share.
  • Uniqueness: No duplicate ownerId values allowed.
forwardApplication(ctx, applicationId, forwardDataStr)
2 Guards Added

Before advancing the stage in the multi-org workflow, the chaincode checks:

  • Guard 1 (Dispute Freeze): If application.isDisputed === true, throws "Application is FROZEN due to an active ownership dispute".
  • Guard 2 (Consent Gate): If application.ownershipType === 'joint' && !application.allConsentsGiven, throws "Cannot forward: Not all co-owners have given digital consent".

4. The 5 New Chaincode Functions

1. addCoOwnerConsent(ctx, applicationId, ownerId, consentDataStr)
New Function

Called by a co-owner to submit digital consent.

NameTypeExample
applicationIdstring"APP-101"
ownerIdstring"OWNER-02"
consentDataStrJSON string{"remarks": "I consent to 40% share"}

Behavior: Marks the owner's status as approved. If all co-owners have approved, sets allConsentsGiven = true, immediately unlocking forwarding.

2. raiseOwnershipDispute(ctx, applicationId, raisedBy, reason)
New Function

Raised by any listed co-owner if share allocation or terms are incorrect.

Parameters: applicationId, raisedBy (ownerId), reason (string).

Behavior: Sets isDisputed = true and populates disputeDetails. Freezes application flow until Org3 resolves it.

3. resolveOwnershipDispute(ctx, applicationId, resolutionDataStr)
Org3 Collector Only

Only identities with MSP Org3MSP can invoke this function.

Option A: Rectify Shares (In-line Correction):

{
  "action": "rectify_shares",
  "decision": "Collector order: adjusted Suresh to 50%",
  "orderNumber": "DC/ORDER/2026/88",
  "updatedOwners": [
    { "ownerId": "OWNER-01", "sharePercent": 50 },
    { "ownerId": "OWNER-02", "sharePercent": 50 }
  ]
}

Updates the shares in-place, validates that new sum is 100%, unfreezes the application (isDisputed = false), and records a full audit log in history.

Option B: Reject (Permanent Termination):

{
  "action": "reject",
  "decision": "Fraudulent share submission proven. Application rejected.",
  "orderNumber": "DC/ORDER/2026/89"
}

Sets status = 'rejected' and clears dispute freeze. A fresh application must be filed.

4. transferOwnershipShare(ctx, applicationId, fromOwnerId, toOwnerId, sharePercentStr, newOwnerDataStr)
New Function

Transfers partial or full share post-registration (when status === 'completed').

  • Transfer to existing co-owner: Pass newOwnerDataStr = '{}'. Shares adjust between the two.
  • Transfer to new third-party buyer: Pass newOwnerDataStr = { "name": "...", "aadhar": "...", "nocApprovals": ["O2", "O3"] }. Requires NOC approval from all remaining co-owners.
  • If seller's share drops to 0%, they are cleanly removed from the owners[] array.
5. getOwnershipDetails(ctx, applicationId)
Read-Only Query

Returns complete ownership state, consent progress, dispute info, and helpful computed flags for UI like canBeForwarded.
