3. Critical Gaps & Bugs (High Priority)

🚨 Gap 1: Dispute Resolution Route & Payload Mismatch (Will Crash / 404)

In admin-dashboard/page.tsx (lines 287-294), the dispute resolve handler is coded as:

client/src/app/admin-dashboard/page.tsx (Line 287)Broken Next.js Fetch
// Frontend calls non-existent Next.js relative route with POST
const response = await fetch('/api/land/dispute/resolve', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    receiptNumber: disputeApp.receiptNumber,
    resolution: disputeResolution,
  }),
});

Why this fails:

  • ❌ Wrong URL & Method: In Express jointOwnershipRoutes.js, the route is PUT http://localhost:3001/api/land/:id/dispute/resolve. Calling POST /api/land/dispute/resolve on Next.js port 3000 returns 404 Not Found.
  • ❌ Missing action Field: The chaincode requires action: 'rectify_shares' | 'reject'. Because action is missing, chaincode throws: "Unknown resolution action 'undefined'".
  • ❌ Missing orderNumber & updatedOwners: The chaincode requires updatedOwners: [{ ownerId, sharePercent }] for rectification. None of this is passed from the UI.

🚨 Gap 2: Wrong Persona for Dispute Resolution (Admin vs District Collector)

In our legal/architectural design, Org3 District Collector (Quasi-judicial authority) resolves disputes. Officials log into /officiallogin with designations like districtcollector or jointcollector.

  • ❌ Member 2/3 placed the "Resolve Dispute" modal in admin-dashboard/page.tsx (which is intended for Super Admin system maintenance).
  • ❌ In official-dashboard/page.tsx, when a District Collector logs in, there is zero interface to filter or resolve disputed land applications!
  • ❌ In admin-dashboard/page.tsx, applications are loaded from MongoDB (/api/admin/applications), but isDisputed is stored on Hyperledger Fabric! Therefore, (app as any)?.isDisputed will always evaluate to undefined, so the button never appears for blockchain records!
